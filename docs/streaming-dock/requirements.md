# 製品コンセプトと要求仕様

[仕様と進捗の概要](README.md)

基準：構想仕様 v0.6、2026年11月20日。C＝確定要求、P＝設計提案、O＝未決定、V＝実機検証待ち。確定要求は実装済みを意味しません。

## 1  要求とハードウェア仕様の基準

Q1〜Q16とCubie A7S・VRC-01での初回試作方針を反映した仕様基準である。必須機能、実現を目指す機能、実装提案を区別し、未確認の性能を確定値として扱わない。

| ID | 項目 | 区分と仕様 |
| --- | --- | --- |
| H01 | 対象用途 | C  トーク／対談、音楽／演奏、イベントを優先。ゲームは優先度を一段下げ、1080p60で使える範囲。 |
| H02 | 端末とアプリ | C  USB-C iPhone／iPad／Android。アプリで映像切替・合成・配信を行う。 |
| H03 | HDMI入力 | C  1入力、1080p60を必須とする。映像取得から端末への転送まで60fpsを維持する。 |
| H04 | HDMI出力 | C  1080p60パススルーを実現できれば搭載。4K／HDR／VRR／120Hzは初期対象から外す。 |
| H05 | マイク入力 | C  XLR／TRS系の2入力、48Vファンタム。P  コンボ端子、入力別48V切替。Hi-Z不要。 |
| H06 | 音声ミックス | C  DockのLinuxでミックスとFXを処理。P  配信全体、ゲスト返送ベース、モニターを別バス化。 |
| H07 | 直接モニター | C  Dock内で直接モニター、ヘッドホン1人分。O  端子径、原音／FXの聴こえ方。 |
| H08 | 配信用FX | C  HPF、EQ、コンプレッサー、ゲート、リミッター、リバーブが目標。日程／負荷に応じ機能を縮小。 |
| H09 | USBと制御 | C  UVC／UAC、USB Ethernet、MIDI制御。P / V  同時公開し、アプリが利用する転送を選択。 |
| H10 | Dock電源 | C  USB PD給電。P  電源入力と端末接続に別々のUSB-C端子を設ける。 |
| H11 | 端末充電 | C  可能なら実現する希望機能。V  端末のデータHost動作を維持したまま給電。 |
| H12 | 配信回線 | C  端末のWi-Fi／携帯回線。P  USB EthernetはDockとの専用リンク。 |
| H13 | 形状と接続 | C  短いUSB-Cケーブルと、スマートフォン〜iPadを立てかけて保持できるDock。 |
| H14 | 状態表示 | C  小型OLEDを搭載する構想。O  3型以下を目安にサイズ・解像度・物理操作を決定。 |
| H15 | BGMと通話 | C  BGM／SEをDockでmix。WebRTC＋招待リンク、ゲスト映像も初期想定。実証1人、Cloudflare TURN。O  製品人数。 |
| H16 | LINE入力 | C  3.5mmステレオLINE端子×1を採用方針。マイク2本と同時使用する独立2ch入力。 |
| H17 | 価格と数量 | C  税込5万円以下、直販中心、約3,000台。AC・ケーブル同梱なし。アプリ／通話の別料金も検討可。 |
| H18 | 実装の優先順 | C  Linux音声処理を基本とし、日程または処理負荷の制約が厳しい場合は、まず機能削減で対応する。 |

初回試作はCubie A7S。ゲストの音声と映像を含め、1080p60、基本mix、直接monitorを検証する。パススルーと端末充電は実現目標。VRC-01を使う試作構成は[第16〜18章](prototype.md)。

## 2  用途と競合から見た製品の位置づけ

製品コンセプトは「スマートフォン／タブレットに、HDMIとマイク2本の配信機能を追加する」とする。以下の差別化は公表仕様からの企画上の仮説であり、価格優位や市場での評価は未検証である。

| 比較項目 | Roland AeroCaster | Shiftall HOMRA 4K | 今回の構想 |
| --- | --- | --- | --- |
| 中心となる機器 | iPadのLIVEアプリ＋VRC-01 | 単体の映像処理・配信機器 | iPhone／iPad／Androidアプリ＋Dock |
| 映像入力 | 無線カメラ等。HDMI有線入力は非対応 | HDMI、3G-SDI、UVC等 | HDMI 1入力・1080p60 |
| 映像の上限 | 入力1080p30、映像出力1080p60 | HDMI 4K60入力、4K60配信・録画を公表 | 1080p60取込み必須。パススルーは希望 |
| 音声 | 2 XLR／TRS・48V、FX、直接モニター | 3.5mmライン入出力と埋込音声のミックス | 2マイク・48V、3.5mm LINE、Linux mix／FX、遠隔ゲスト |
| 製品の状態 | 日本公式は販売完了 | 2027年3月発売予定、10万円程度予定、開発中 | 企画検討中。税込5万円以下、直販、約3,000台 |

確認日 2026年11月20日。AeroCasterのiPhone／Android対応は主にカメラ側で、主配信アプリはiPad向け。HOMRAのHDMI OUTは公表されているが、HDMIの無処理ループ出力や専用iPhone受信アプリは確認できない。[S25–S29](references.md#s25)

### 優先する用途と次の設計判断

| 用途 | 共通機能で対応する範囲 | 追加で決めること |
| --- | --- | --- |
| トーク／対談 | 2マイク、音量管理、字幕と画面切替 | WebRTCと招待リンク、ゲスト映像も初期想定。1人で実証し、製品人数を決める。 |
| 音楽／演奏 | 48V、直接モニター、配信用FX | Hi-Z不要、ヘッドホン1人。Linux音声の遅延と採用FXを検証する。 |
| ゲーム | HDMI 1080p60、実況マイク | 優先度を一段下げる。1080p60パススルーを実現目標とする。 |
| イベント | カメラ映像、会場音声、状態表示 | 3.5mmステレオLINE。許容入力・連続時間・設置方法を決める。 |

AeroCasterには2マイク・48V・FX・直接モニターが既にあるため、これら単独を差別化にしない。有線HDMI 60pとスマホを主配信端末にする体験が比較軸になる。HOMRAに対してはアプリの画面操作と音声入力の統合を軸とし、単体4K配信機との機能数競争を前提にしない。[S25–S29](references.md#s25)
