## 9  Cloudflareを使うWebRTC通話

C  WebRTC＋招待リンク、初期実証ゲスト1人、Cloudflare TURNを基本とする。P  ホストとゲストの直接P2P接続を候補に残し、接続条件に応じてTURNを利用する。SFUは人数・通信構成を拡張する段階で判断する。[S47,S50](references.md#s47)

| 構成要素 | 役割 |
| --- | --- |
| ikakim／ゲスト画面 | ホストはネイティブ音声経路へWebRTCを統合。ゲストはHTTPS招待ページで参加。音声・映像の送受信を行う。 |
| Cloudflare Worker | ルーム作成、招待・参加の確認、期限付きTURN資格情報の発行API。長期secretはバックエンドに保持。[S48](references.md#s48) |
| Durable Object | ルームごとの参加状態、SDPとICE candidateの交換。WebSocketで接続を仲介し、休止機構も検討。[S51](references.md#s51) |
| Cloudflare STUN／TURN | 接続候補の発見と必要時の中継。UDPに加えTCP／TLS経路を評価。TLSの443番も候補にする。[S47](references.md#s47) |

音声・映像はWebRTCの直接／TURN経路で転送し、Worker／DOは接続制御を担当する。端末には期限付き資格情報だけを提供する。通話時間に対応したTTL、更新、ICE restart、回線変更後の復帰を実証する。[S48,S50](references.md#s48)

### 中継料金はWebRTCの圧縮後データ量で計算する

確認日2026年11月20日。Realtime SFU／TURNは月最初の1,000GBが共有無料枠、超過は$0.05／GB egress。Workers／DOは別料金体系。TURNはサーバー→TURNクライアントの送出を計測し、認証後のTURN overheadを含む。[S49–S50](references.md#s49)

| 課金対象レートの仮定 | 1時間の概算量 | 無料枠超過後 |
| --- | --- | --- |
| 合計2Mbps | 0.9GB | $0.045 |
| 各方向2Mbps、合計4Mbps | 1.8GB | $0.09 |

計算は0.45×合計Mbps×時間＝GB（10⁹ bytes）。上表は追加ヘッダー・再送等を含まない単純例で、通話品質の推奨値や請求額ではない。双方向を合算済みなら、両端がrelayという理由でさらに2倍しない。

DockとのPCM 9.216MbpsはUSB内部の値であり、この料金計算に使わない。ゲスト通話の画質・fps・音声形式はHDMI 1080p60要件と別に決める。運用費は稼働台数、通話時間、TURN利用率、実egressに基づいて算出する。

### 初期実証で確認する接続条件

直接接続、TURN強制、UDP不可時のTCP／TLS、Wi-Fi／携帯回線の切替、資格情報更新と再接続を検証する。ゲスト映像を含む通話を実証する。映像停止時の音声継続・復帰も確認し、製品人数と料金は後続で決める。

### 初回実証に用いる仮設定

| 項目 | 提案と確認する内容 |
| --- | --- |
| 人数と映像 | P  ゲスト1人、720p30を上限候補として開始。回線に応じ画質を調整。HDMIの1080p60と製品最大人数は別条件。 |
| 受信映像 | P  モバイルアプリがWebRTCの映像を復号し、独立した映像入力として切替・合成。Dockへゲスト映像を送信する経路は設けない。 |
| 受信音声 | P  アプリ→GUEST_RETURN→Linux mix／FX→PROGRAM→アプリ配信。WebRTCの標準再生を併用せず、アプリでも音声を再加算しない。 |
| 同期 | P  WebRTC時刻とアプリ時刻、Dock音声時刻を対応づける。Dock往復・FX・SRC分を測り、上限付きの映像キュー等で同期する。 |
| ゲストへの映像 | P  初回はホストが選ぶローカル映像1本。配信合成画面の返送はO。返す映像とLOCAL_MEDIAの同期も評価する。 |

端末側は圧縮HDMI映像とゲスト映像の復号、合成、配信用符号化、ゲストへの映像送信を同時に行う。非圧縮UVC入力ではHDMI映像の復号は不要。各処理の同時成立と発熱、符号化の共有可否を実証する。

### 音声と映像の遅延を別に管理する

WebRTCが受信した時点の同期だけでは、追加したDock音声往復の遅延は補償できない。ゲスト音声が配信用PROGRAMへ入る時刻を基準に映像を整合させる。配信の同期調整を直接monitorやゲスト返送へ一律に入れない。再接続時には映像・音声の古いキューを破棄して復帰させる。

### 実証後に決めること

ゲストの保証画質／fps、製品で対応するゲスト人数、返送映像、対応端末、音質指標、モニターFX、物理操作、PD電力と筐体は引き続き設計対象とする。実証時には選択された解像度、fps、codecも記録し、保証範囲を絞り込む。
