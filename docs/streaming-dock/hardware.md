## 3  Cubie A7SとHDMI映像の検証

1080p60は製品要件とし、1080p30は初期の動作確認にのみ使う。入力の可否、CSIでの60fps取得、端末への60fps転送を個別に測定し、最終的にすべてが同時に動作することを確認する。最終配信も1080p60を目指す案とし、保証する合成負荷と端末機種は別途決める。

| 候補 | 公表仕様とUSB Device側 | 採用前に確認すること |
| --- | --- | --- |
| Cubie A7S | Allwinner A733。H.264／H.265最大4K30。USB-C2はUSB 3.2／OTG。 | 31pin 0.3mm・4lane CSIへの配線変換。1080p60の実符号化経路、I2S引出し、UDC資源。 |
| Cubie A7A | A733。USB-C OTGはUSB 2。USB 3.1 Type-AはHOST。 | A7SとはUSB構成が異なるため、正確な型番を確認する。 |
| Radxa ZERO 3W | RK3566。H.264／H.265 1080p60。USB Device側はUSB 2。 | IP転送候補。非圧縮1080p60 UVCは不可。CSI 22pinの配線・BSP互換は要検証。 |

メーカーの符号化上限はこのDockでの連続動作を保証しない。初回のバラック試作はCubie A7Sとする。A7A／ZERO 3Wは構成差の比較資料として残す。A7S向け公式手順にはOpenMAX経由のH.264／MJPEGがあるが、利用可能なプラグインはOSイメージで異なる。[S08–S12,S15](references.md#s08)

### HDMI入力回路の選択

| 構成 | 役割 | 扱い |
| --- | --- | --- |
| C790 | TC358743によるHDMI→CSI。公表上限1080p60、I2S音声出力。 | 初期接続候補。A7Sとの変換配線・BSPを実証する。符号化器やHDMI loopは含まない。[S13](references.md#s13) |
| C792等 | 公式Overviewは4K60入力／ループと1080p60への縮小を公表。 | パススルー回路の比較資料。1080p60だけに必要な構成と比較し、採用SKU・版を実測する。[S30](references.md#s30) |

C790／C792のRaspberry Pi向け実績をA7S／ZERO 3Wの互換性と同一視しない。4laneの配線、I2C、reset、電圧、CSI受信、動的なHDMI形式変更、色変換から符号化までを通して確認する。[S11,S13–S14,S30](references.md#s11)

### 転送帯域と映像形式

非圧縮1080p60はYUYV 16bitで1,990.656Mbps、NV12 12bitで1,492.992Mbps。計算は1920×1080×60×bit/画素で、通信オーバーヘッドを含まない。USB 2では不足するため圧縮映像を使う。USB 3 UVCも端末・ケーブル・Dockの実速度で判定する。

初期提案はSDR・8bit・非HDCPの映像とLPCMステレオ音声。59.94／50Hz、RGB／YCbCr、範囲・色域、HDCP時の表示、EDIDとホットプラグを仕様化する。4K受理、4Kループ、HDR、VRR、120Hzは初期対象から外す。パススルーは外部画面へ直接出力する経路とし、アプリ経由の再出力と区別する。EDID、HPD、追加遅延、入力断からの復帰を検証する。

## 7  音声回路とLinuxへの接続

### アナログ4入力、ヘッドホン1系統

| 入力／出力 | 基本設計への反映 |
| --- | --- |
| マイク2ch | XLR／TRS系2入力、バランスマイク前段、アナログgain、48V。入力別48V切替と切替時ミュートを提案。Hi-Z不要。 |
| ステレオLINE 2ch | 3.5mm stereo TRS×1、アンバランスL/R。マイク2本と同時使用する独立入力。許容最大レベルと入力インピーダンスは回路選定時に決める。 |
| ヘッドホン | 1人分のステレオ出力。DAC 2ch＋HPアンプ。端子径、駆動負荷、最大出力、FXの聴こえ方は未決定。 |
| デジタル入力6ch | HDMI 2ch＋BGM／SE 2ch＋ゲスト2ch。アナログ4chと合わせ内部論理入力は10ch。 |
| SoCとの接続 | ADC 4ch→SoC/Linux、SoC/Linux→DAC 2ch。HDMI音声は独立クロックの入力ポートで取得する案。I2S／TDM・pinmux・BSPを検証。 |

USBの4in／4outは端末との論理バスを転送するチャネル数。codecの物理4入力／2出力や、HDMI音声用ポートとは別の数である。前版の「専用DSPとSoCをTDM 4chで接続する案」は初期構成から外す。

### codecと前段回路の選定

4ADC／2DAC、I2S／TDM、クロック構成、ALSA／ASoCドライバ、入力レベル、音質で比較する。XLRプリアンプ、48V、LINE入力整合、ヘッドホン駆動はcodecとは分けて設計する。固定機能の変換器・クロック整合回路の使用は、Linuxでmix／FXを行う方針と両立する。

A7S／ZERO 3Wで、ADC 4ch＋DAC 2chとHDMI音声の同時入力を成立させる配線、TDM slot、master／slave、DMAとドライバは未実証。ソフトウェアの再サンプリングでは物理入力ポートの不足を解消できないため、基板選定の初期段階で確認する。

### 6種類のFXを目標として、採用範囲を調整する

| 処理位置 | 初期提案 |
| --- | --- |
| マイク入力ごと | HPF、EQ、コンプレッサー、ゲート。個別ON／OFFとし、基本処理を先に実証する。 |
| ローカル用センド | リバーブは共有1系統から評価。入力ごとにセンド量を設定する案とし、独立した複数リバーブは初期前提にしない。 |
| 配信用PROGRAM | ピーク保護用リミッター。先読み時間を含む遅延と、返送／monitorへの影響を分けて測る。 |
| 未決の詳細 | EQバンド数、処理順、ゲート特性、リバーブ方式、LINE／HDMIへのFX範囲、dry／wetモニター。 |

## 11  USB PDとDockの形状

### Dockの給電と端末充電を分けて設計する

USB PDによるDockへの給電は要件とし、端末充電は実現を目指す追加機能とする。電源入力用USB-Cと端末接続用USB-Cの2端子案を採る。受電した電力をSBC、低雑音の音声電源、48Vファンタム、OLEDへ配分する。

| 場所 | 役割 | 回路として必要なもの |
| --- | --- | --- |
| PD IN | 外部電源から受電するSink | PD交渉、入力保護、電圧変換。受電電圧をSBCの電源へ直接流さない。 |
| 端末ポート | DockはデータDevice | USB差動線、接続検出、VBUS管理。外部給電と端末側VBUSを無条件に直結しない。 |
| 端末充電の追加 | 端末はデータHost＋電力Sink。DockはDevice＋Source | 端末側にもPD／役割制御、給電スイッチ、電力配分が必要。USB Gadget設定とは別。 |

USB-Cではデータ役割と電源役割を分けて扱う。STUSB4500等のPD Sink制御例と、TIの給電対応Dock参照設計を回路検討の資料にできる。これらを採用部品と決めたものではなく、スマホ互換性は実機で確認する。[S19,S31–S32](references.md#s19)

電力予算は「映像部＋音声部＋48V負荷＋表示＋変換損失＋端末への給電電力＋余裕」の合計で算出する。ACアダプターとケーブルは同梱しない。実測後に必要なPD電圧・W数とデータケーブルの規格を指定し、購入前に確認できるようにする。充電マークだけでなく、配信中の端末残量が維持・増加するかを検証する。

### 短いケーブルと可変の支持台

利用者が用意する交換可能な短いUSB-Cデータケーブルと、端末を立てかけて保持する支持台を基本とする。最大iPad寸法、ケース厚、縦横、角度を仕様化し、XLR／HDMIケーブルの引張りや画面タッチで転倒しないよう設計する。端末とケーブルの荷重をUSBコネクタに集中させない。

筐体寸法はXLRコンボ2個、独立LINE、ヘッドホン、電源と放熱で決まる部分が大きい。ファンレスは提案として検討し、1080p60＋FX＋48V×2＋端末充電の同時動作で温度と騒音を測定する。

### 表示と物理操作の初期案

| 要素 | 提案 |
| --- | --- |
| OLED | HDMI形式、Mic 1／2・LINE・配信レベル、48V、端末接続、選択経路、配信状態、給電不足・温度。 |
| 基本操作 | Mic 1／2のmute、ヘッドホン音量、簡単な選択／決定操作を候補とする。 |
| 拡張操作 | マイクのgain／level、FX量、配信開始、映像切替の物理操作は価格と操作距離から判断。 |

ヘッドホン未接続時のOS音声ルートとConnector Controlを確認する。アプリ終了やUSB断でも直接モニターを維持する動作を提案し、アプリから受信するBGMはフェードアウトして停止し、配信状態の表示は不明に変更する。[S04](references.md#s04)

## 13  税込5万円以下・直販・3,000台の条件

C  税込5万円以下、直販中心、想定約3,000台。ACアダプター・ケーブルは同梱しない。アプリ／ゲスト通話の別料金も検討可能。量産BOMと工場見積は未取得であり、価格成立は未判定。

### 直販を基準に製造費の許容範囲を考える

仮に税込49,800円、消費税10%で計算すると税抜売上は約45,273円。49,800円は試算値であり決定価格ではない。直販でも決済、配送、返品、保証対応等の費用を見込む。[S46：税率のみ](references.md#s46)

| 製造費の仮定／1台 | 開発費回収5,000円 | 開発費回収10,000円 |
| --- | --- | --- |
| 15,000円 | 残額22,273円 | 残額17,273円 |
| 20,000円 | 残額17,273円 | 残額12,273円 |
| 25,000円 | 残額12,273円 | 残額7,273円 |

残額＝45,273円−製造費−開発費回収−その他変動費3,000円（仮定）。その他固定費、継続開発費、利益に充てる額であり利益予測ではない。製造費には基板・筐体・組立検査・包装を含め、同梱しないAC／ケーブルは除く。

### 初期開発と量産方式を比較する

| 項目 | 今回の方針 |
| --- | --- |
| 開発費回収 | 3,000台すべてを販売する仮定で、1,500万円÷3,000＝5,000円／台、3,000万円なら10,000円／台。開発費の実見積ではない。 |
| 試作 | Cubie A7S＋所有するVRC-01でLinux音声処理を先行して検証する。続いて独立4入力のcodec／前段回路、HDMI、複合USBを実証する。 |
| 量産の比較 | SoM＋独自音声／電源基板と、SoCからの独自基板を比較。単価差に加えDDR・BSP・高速配線・試験の開発費を含める。 |
| 追加機能 | HDMIパススルーと端末充電は、部品費・電力・開発工数を別枠で見積もる。 |

追加開発費÷想定販売台数と、1台当たりの製造費削減を照合する。例えば追加開発費300万円は3,000台で1,000円／台。販売数量が減った場合も再計算する。

### ハードウェア価格とサービス料金を分ける

アプリ／ゲスト通話の別料金は選択可能な事業方針で、課金方式・金額は未決定。通話の実利用量とTURN／Workers等の費用、サポート、継続開発を計測し、買切り・月額・利用枠等を比較する。

AC・ケーブルを同梱しない分、必要なPD電源、USBデータ対応、必要速度・長さ、確認済み機器の案内を製品仕様へ含める。付属品削減だけで原価成立を判断しない。
