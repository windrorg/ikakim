# 実証の順序と判定条件

[仕様と進捗の入口](README.md)

基準：構想仕様 v0.6、2026年11月20日。C＝確定要求、P＝設計提案、O＝未決定、V＝実機検証待ち。確定要求は実装済みを意味しません。

## 14  検証の順序と合格条件

Cubie A7SのOSとUSB-C2 Gadget動作を確認後、音声とHDMIを分けて立ち上げ、ゲスト映像まで統合する。音声先行は検証順であり、ゲスト映像は初期の実証範囲に含める。

| 段階 | 試験 | 合格に向けて確認する内容 |
| --- | --- | --- |
| 1 | 音声I/Oと基本mix | VRC-01のstereo／2マイク分離で先行。独立4ADC／2DAC、48V×2、I2S／TDM、HDMI音声口は後段で確認。 |
| 2 | Linux音声の連続動作 | 基本mix、4バス、返送、選択FXを段階的に追加。xrun、処理時間、起床遅延、FIFOの推移を記録。 |
| 3 | HDMI 1080p60 | CSI→色変換→符号化→端末受渡し。fps、欠落、遅延、信号断、EDID、任意パススルーを確認。 |
| 4 | 複合USBと回線 | UVC／UAC／MIDI／NCMの同時列挙、4in／4outまたはIPバス。端末の配信回線と通話を維持。 |
| 5 | ゲスト1人の通話 | 音声＋映像、招待、直接／TURN、回線変更。本人の声が返らずBGMが1回届き、配信A/Vが同期する。 |
| 6 | 全負荷と電源・熱 | HDMI 1080p60＋ゲスト映像＋採用FX＋全入力＋48V。発熱、PD、追加時の端末充電も確認。 |

### 初期の測定目標と判定条件

| 項目 | 区分と暫定目標 | 測定条件 |
| --- | --- | --- |
| 映像 | C  HDMI 1080p60。P  59.94pも評価。 | 入力→端末受渡しのfpsとdrop。配信fpsは端末と合成負荷を固定。 |
| 直接モニター | P  主音経路10ms以下、乾音5ms以下を目指す。 | マイク端子→HP端子を実測。ALSAのperiod値と区別し、FXと負荷を記録。 |
| 映像取込み遅延 | P  HDMI→アプリ合成入力100ms以下を開始値とする。 | 符号化・転送・復号を含む。プレビュー表示と配信先到達は別測定。 |
| A/V同期 | P  ±40msを初期目標。 | 長時間運転、HDMI断・通話再接続。返送とmonitorへ配信遅延を入れない。 |
| 連続運転 | P  2時間から8時間へ拡張。 | 製品で有効にする最大機能セットで音切れなしを目指す。平均CPUに加え最大処理時間を記録。 |
| 音質・電力 | O  回路選定時に基準を決定。 | EIN、THD+N、headroom、48V負荷、HP出力、PDノイズ、消費電力。 |

Pは性能保証ではない。音声の実測結果からFX範囲を調整し、変更後の機能セットで全負荷試験を行う。USB／HDMI断、アプリ終了、音声サービス再起動の影響を分けて確認する。
